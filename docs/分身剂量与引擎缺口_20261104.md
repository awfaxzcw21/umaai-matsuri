## 2. 剂量（我按回合算的数，#51 没算过这个）

```
sub_sum（该板分身占位数）分布 = {0: 219, 1: 48, 2: 54, 3: 20, 6: 9, 7: 18}   均值 1.08
heads_sum（该板人头总数，已含分身）中位 13、均值 14.3
  按 sub_sum 分组：0→11.6  1→15.9  2→18.5  3→18.8  6→21.8  7→21.1（单调，heads 不是减去分身的口径）

其余 t_period≠3 ：sub 均值 0.63 / heads 均值 13.7（n=341）
```

⇒ 分身密度：**全期约 0.22 个/格**（1.08÷5 格），**末段约 1.33 个/格**（6.67÷5），非末段 0.13 个/格。
注意 heads_sum 与 sub_sum 单调同涨不等于分身抬了人头——有分身的板本身是更后期的板（卡更多、NPC 更多）。
**这句话只到「剂量」为止，不能推「分身让板更值」。**

## 3. 引擎缺口（代码可证，不是猜测）

- **剧本侧不生成分身**：全仓 `effect_type == 18` 没有消费者。`advice_scope` 只在
  `crates/matsuri-core/src/game/mod.rs:167` 声明 `(801, 18) => (true, true)`（作用域表），
  两处真正吃效果的 `match row.effect_type`（`:996` 教诲腿、`:1033` 稽古腿）只列 13/21/203/202/3…
  且都以 `_ => {}` 收尾 ⇒ **18 落到空臂**；`advice_value()` 从无 `18` 的调用点（唯一调用点 `:782` 传 16）；
  `sub_partners` 在全仓 `crates/**` **零命中**（`state.rs` 的重建器只读 `training_partner_array`）
  ⇒ 表里的「1 个分身」在模拟里**没有落点**。
- **上游底座把 `distribution` 的负数条目当「空位」**：`E:/HJM/umaai_next/crates/umasim/src/game/traits.rs:423-433`
  的 `count_training_persons` 只数 `p >= 0`，`:444-449` 的 `default_calc_training_buff` 也跳过负数
  ⇒ 负数既不吃人数加成也不吃卡加成。同一个文件 `:421` 的注释却写「分身不新建人头而是再放占位，
  因此按占位逐个计数，不去重」——**注释与代码互相矛盾**。按「上游缺陷只留本地文档、不外报」处理，
  登记于此，不提 issue、不改对方仓。
- 净效果：**只要走全程模拟（从 t1 或从 t30 往后自走），板上的分身数恒为 0**；真机同期是 1.08/板。

## 4. 为什么这一手不接线（以及「有没有实现可抄」的正确答案）

接线的最小形式要往训练格上塞 1–2 个「分身人头」，而**它值多少没测**：

- 分身进不进**人数加成**（`count_training_persons` 那一项）？
- 分身带不带该卡的**友情/卡加成**（真机的分身是同一张卡的缩小版，理论上带友情；上游代码把负数全跳过）？

任一个都决定这条腿是 +几个% 还是 +几十%。拿现有的人头项当「价」来填，就是**用没验过的结构去换数量**——
按机制真实性铁律，宁可登记为缺口。

**姊妹实现存在，但它的落点口径和一手冲突，不能直接抄。** 黑板自己的 Python 模拟有分身
（`E:/HJM/jidianbeiAI0.22/sim/engine.py:1148-1177`）：`act_dups()` ＝「该演目组里每张支援卡额外出现一次」
（与 #51 的 presence 规则、#47 的「每来源 1 槽」一致，✅）；但 `extra_persons()` 的注释自己写
「分身额外出现在**随机 1 个训练位置**」，于是把总分身数**均摊到 5 格**（`total / max(len(s.acts),1)`）。

#47 §2 的落点一手不是「均匀 5 格」，而是**带两条排除**（3,350 条报文级标记 / 729 唯一板标记，**0 反例**）：
分身不落本体当天已站着的训练类型、不落该卡自己担当演目的 510x。
两侧的分布正好把这个差别照出来——落点 `{速429 力770 根745 耐684 智722}` 近乎均匀，
而来源卡的本体严重偏速度 `{速399 力121 根7 耐108 智64}`
⇒ 真实形状是「从 5 类里抽、**抽掉本体自己那类**」，分身不会给它自己那张卡站着的那格加人。
所以均摊口径的偏差方向是**高估卡密集的那格**（速 429 ＜ 其余 684–770，真机明显绕开它），
也就是真机比面板模型更把人头推向「本方卡组没站人」的格——**对「该练哪一格」不是中性的**。
面板另外用 `advice_fit(801) = 1 + 0.70 × 组内卡数`（`:1190-1196`）做教诲落位打分，
是在**已经摊平的人数**之外另开的一条腿，不等于修正落位口径。
⇒ 这条偏差**回报给面板线**（它是我们自己维护的仓），本仓不替它改，也不把它当已验语义移植过来。

## 6. 门禁读数受不受影响

实测 `_state_t30.json` 五格 `sub_partners` ＝ `[] / [] / [] / [] / []` ⇒ 该板真机分身数 0；
再叠一条独立证据：#47 §0 观测「分身只出现在**报文回合 37–78**」，锚点板是引擎 30＝报文 31，
在它之前 ⇒ **结构性为 0**，不是抽样碰巧。所以配对 CRN（锚点在 t30）对这条**不敏感**；
受影响的只有**从 t30/t1 往后自走的整局投影**，方向＝**下偏**（少 1.08 个/板的人头与可能的友情腿）。
⇒ 报 LG15 缺口时，这一条与 `forced_target` 兜底（第 4 条虚高，方向＝上偏）**符号相反**，
两个都不能省，也别互相抵掉不谈。
