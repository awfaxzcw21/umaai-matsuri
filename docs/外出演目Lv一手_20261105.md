## 2 引擎现状与差（读码，非建议）

`game/action.rs:53-60`，`Action::Outing` 一次做三件事：

```rust
game.do_outing(rng)?;          // mod.rs:384  vital+51  +  rng.random_range(0..5) 那格 Lv+1   ← 无一手出处
game.push_act_gauge(1);        // mod.rs:1263 演目槽 +1，argmin(Lv,槽,下标)、满槽跳过        ← 与 C 组一致
game.bump_lowest_act_level();  // mod.rs:1291 一格 Lv+1，argmin(Lv,槽) 严格 < 保持小下标    ← 与 C2/C4 同形状
```

- **`bump_lowest_act_level` 已经是正确的友人腿**：`(act_level[i], act_gauge[i])` 严格比较 + 先到先得
  = `argmin(Lv → 槽 → 下标)`，且**不排除满槽** —— 与 C4 的 3,308/0 逐字对齐。
- **`do_outing` 里多出的随机 +1** 是纯占位：注释写「推友人事件」，但友人腿已由 `bump_lowest_act_level` 表达，
  两条同时跑 ⇒ 引擎每手外出送 **2 级**，真机送 **1 级**（友人）或 **0 级**（普通）。
  随机还把其中 1 级撒在错误格上（真机落点由 F 指针定，非均匀）。
  `traits.rs:111` 把 `Action::Outing` 的候选限量在 5 次/局 ⇒ 名义多送 ≤5 级/局，
  **量级不在此估**，由配对 CRN 判（铁律：不给拟合数）。
- 引擎**不按 `command_group_id` 分叉**：390（友人）与 301/304（普通）在 `Action::Outing` 里同一条路。
  真机侧这两条的 Lv 腿不同（1 格 vs 本库 0 格），槽腿相同。
- `Self::Clinic`（入院）不调 `push_act_gauge` —— 与隔壁 §2「ct=8 恒 0 点，704/0 违例」一致，这条是对的。
- `do_outing` 的 `vital+51` 与 5 段/局（表侧 `single_mode_15_outing_effect` = 2 卡 × 5 段 × `add_level=1`）
  **本次未裁**，隔壁报告也没裁它。
