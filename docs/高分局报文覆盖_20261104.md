## 1. 结论（五句）

1. **LF 段的逐回合报文 = 0 局**。抓包里 ≥91,400 的练成马娘有 **47 张**（全部 scenario 15、41 个别的 viewer），
   没有一张属于自己账号（viewer `238107205`），也没有一张带逐回合轨迹。最高分 94,372
   （viewer `112388649`、card `106301`、route 93）——就是最想要的那局，**只有终值，没有过程**。
2. **LF 段的终值本身是一手的、可读的**，而且不止一个数：`rank_score` 之外，五维逐轴、115 条技能（含 grade）、
   6 张支援卡（含 exp/限界break）、18 场赛的 turn+名次、继承 6 头、因子 32+11、`total_skill_pt`、
   `scenario_data_array` 全在报文里（见 §4）。**缺的是时间轴，不是内容**。
3. **逐回合覆盖并不缺 t29–t48**：自己 13 局（全 scen15、全 viewer `238107205`）里 **9 局打到 t78** 并且终值报文里读得到，
   其中 **7 局 t29–48 满命中 20/20、8 局合宿窗口 t37–44 满命中 8/8**；只有 171 缺 t42–48、179 缺 t29。
   真正的缺口是**分数段**（自己最高 71,319 派生 / 72,142 官方），不是回合区间。
4. **演目/训练意图字段能读到**，但是三段拼图而不是一个「意图」字段：实际执行的动作、这次动作是不是自动方案发的、
   自动方案背后的玩家声明配置（`auto_setting_info`，即游戏里的「教えセット」）。详见 §5。
5. 口径自检通过：派生分 vs 官方 `rank_score` 的 |差| **中位 232 / p90 655**（n=3,548）；
   9 局配上面 71–976。**没有为凑分拟合任何系数**，k 用已定案的 1.0746（scen15）。

## 4. LF 段 47 张里读得到什么（一手，非推测）

来源路径分布：`.ranking_user_list[].trained_chara` 32／`.event_succession_trained_chara_data.succession_trained_chara_array[]` 12／
`.partner_chara_info_array[]` 2／`.directory_card_array[].trained_chara` 1。route 分布 `{93: 20, 30: 4, 134: 3, …}`，
card 分布 `106301` 18 张居首。五维和区间 9,319–9,511；Σgrade 25,502–29,038；`total_skill_pt` 9,782–11,114。

`lf_packet_scan.py` 每次跑都会**回源解码 LF 段最高 3 张**，把可读字段逐条打印（报告里那段
「-- LF 段最高分 3 张：回源解码，一手可读字段清单 --」）。94,372 那张（`234751_0064_notify_response.bin`）实测：

- 顶层 **53 个字段**全在：`viewer_id`／`trained_chara_id`／`single_mode_chara_id`／`card_id 106301`／`scenario_id 15`／
  `route_id 93`／`chara_seed 259503833`／`rarity`／`talent_level`／`create_time 2026-11-01 23:11:28`／全部 `proper_*` 适性
- 分数：`rank_score 94372`／五维 `[2291, 1857, 1804, 1706, 1848]`（和 9,506，**逐轴都过 1,200 软上限**）
- 技能：`skill_array` **115 条**（含 level）／`total_skill_pt 10961`
- 卡组：`support_card_list` 6 张，`exp` 全 **118,185**、`limit_break_count` 全 **4**（LF 前 3 张都满破满级；n=3，外推成「门槛」还差证据）
- 赛程：`race_result_list` **18 场，带 turn**：`[12,16,23,31,32,34,44,54,56,59,60,66,69,70,72,74,76,78]`，
  每场含 `program_id`／`weather`／`ground_condition`／`running_style`／`popularity`／`result_rank`／`result_time`／`prize_money`
- 其余：`factor_info_array` 32／`factor_extend_array` 11／`succession_chara_array` 6／`succession_num`／`fans 527563`／`wins 18`／
  `scenario_data_array = [{type:15001, value:46}]`
- `scenario_data_array` 只有这一个计数器：LF 前三张是 **46 / 46 / 48**；LF 段 47 张整体取值 **{46,47,48,49}**，
  scen15 全体 **30–50**，我们自己的局也到过 **48** ⇒ 它**不是** LF 独有的隐藏分量（一手观测；它到底是什么仍未定，不猜）

**含义**：LF 段能给的只有「18 个比赛回合的锚点 + 终局状态」，回合间的五维/PT/演目/gauge 全部读不到。
`race_result_list` 的 turn 序列是目前唯一的时间轴，密度 18/78 ≈ 23%。

## 5. 演目意图字段：能不能读到？——能，分三层（写全路径）

**(a) 实际执行的动作**（一手，请求包）
`single_mode_exec_command_request_common.command_id`，`command_type=1` 时
`command_id ∈ {5101..5105}` ⇒ `act_type = command_id − 5100`（稽古/演目），
`command_id ∈ {101..106}` ⇒ 普通训练/休息等。该请求体的**全部**键只有：
`command_type / command_id / command_group_id / select_id / current_turn / current_vital / exec_auto_play_plan_id`。
⇒ 没有 `select_act`／`wish`／`target_act` 一类的**前置声明**字段（扫遍 12 种 `single_mode_*_request_common`，见报告 §演目意图）。

**(b) 这次动作是谁下的**——`exec_auto_play_plan_id` 区分手动 / 自动育成，取值只有两个：
`0` = 手动（262 条 exec）、`150101` = 自动方案（210 条）。按局归属（472 条 exec 全部落位，无丢失）：

| 局（chara_id） | plan=0 手动 | plan=150101 自动 |
| --- | --- | --- |
| 168 | 9 | 32 |
| 169 | 0 | 64 |
| 170 | 64 | 0 |
| 171 | 58 | 0 |
| 172 | 56 | 0 |
| 173 | 8 | 0 |
| 179 | 57 | 0 |
| 180 | 1 | 0 |
| 200 | 9 | 0 |
| 201 | 0 | 28 |
| 202 | 0 | 29 |
| 203 | 0 | 28 |
| 204 | 0 | 29 |
| **合计** | **262** | **210** |

⇒ **判「真偏好 vs 影子」有硬字段**：170/171/172/173/179/180/200 全程手动（168 混了 32 手自动），
169 与 201–204 是自动方案 ⇒ 自动局里被执行的命令是影子，手动局里才是玩家真选择。

**(c) 自动方案背后的玩家声明配置**（一手，响应包，**这就是「玩家配好的意图」声明**）
路径 `data.festa_data_set.auto_setting_info`：
- `auto_call_preset_id`：0 或 1（=启用的「教えセット」编号）。759 手自己快照里 **400 手声明非空**、359 手空；
  按局：179(77)/180(1)/200(10)/201–204(各 78) 全程 `=1`，168–173 全程 `=0`（配置是 10-31 之后才在实机里存的）。
- `preset_array[].{preset_id, name, advice_info_array, auto_setting_attach_advice_info_array}`。
  七个 `=1` 的局里内容**逐字节相同**（每局指纹种类=1），实测：
  `advice_info_array` = 5 条融合声明 `{601←101, 701←201, 801←401, 901←301, 1001←501}`；
  `auto_setting_attach_advice_info_array` = 6 个 `id`，每个含 5 条 `(act_type 1..5 → advice_id)`：
  id1=id2=`[(1,401),(2,201),(3,301),(4,501),(5,101)]`、
  id3=id4=`[(1,401),(2,501),(3,601),(4,301),(5,701)]`、
  id5=id6=`[(1,801),(2,1001),(3,601),(4,901),(5,701)]`；preset 2/3 为空。
  ⚠ `id 1..6` 到底是卡位还是训练位、`act_type` 与演目表的一一对应，需要跟实机 UI 对表才能定死；
  **本文件只报「报文里读得到这个矩阵」，不替它编语义**。
- 旁证（负结果）：`data.training_roadmap_selected_info` 在 5,228 份响应里只有 **39 份带这个键、且全部为 null**，
  其余 5,189 份根本没这个键 ⇒ 路线图字段**不能**当意图来源。
- 请求侧也没有前置意图字段：名字含 `act/select/target/plan/intent` 的请求键只有
  `exec_auto_play_plan_id`（=谁下的，见 (b)）与 `select_id`／`factor_order_request`／`factor_lottery_id`，
  没有任何 `select_act`／`wish`／`target_act`。
- 这三段都已落进 CSV：`out/lf_turn_trace_20261104.csv` 新增 `auto_call_preset_id / auto_decl_n / auto_decl` 列。

**(d) 演目的事后状态**（一手，响应包）
`data.festa_data_set.act_info_array[].{act_type, level, act_gauge, need_act_gauge, advice_id, act_training_state}`，
`data.festa_data_set.festa_info.{act_training_step, max_act_level, summer_camp_remain_turn_num}`。
`act_training_state ∈ {0,1,2}`；执行稽古那一刻，**被练那个演目的 state 恒为 1 或 2、从不为 0**，
普通训练时向量为 `(0,0,0,0,0)`（150 手）——所以「这一手练了哪个演目」在响应侧也可独立复核，不只靠 request 的 command_id。

## 6. 要拿到 LF 段一手逐回合，需要用户做的事

**①1 是唯一能直接补上缺口的动作**，其余都是加固：

1. **实机打一局 ≥91,400 的骏大祭，全程抓包**。⚠ 报文目录最后一次落盘是 **11-03 04:49**（今天 11-04 没有新包），
   所以**先把抓包开起来再开这一局**。硬性要求：
   - 覆盖 **t1–t78 每一手**，中途别关面板/断线（171 缺 t42–48、179 缺 t29 就是这么丢的）；
   - **手动打**，别让 `exec_auto_play_plan_id` 变成 150101，否则抽到的是影子（判法见 §5b）；
   - 育成打到 t78 结束，**并且**赛后开一次排行榜页 + 走一次育成完成（终值有两条路径：
     `.ranking_user_list[].trained_chara` 与 `.single_mode_finish_common.trained_chara`，双保险）；
   - 打完别删这局，把 chara_id + 开局时间告诉我，我按 run key 直接抽逐回合 CSV。
2. **在实机里把「教えセット」按真实意图配好并保存**（现在只有 set1，且是 10-31 之后才配的，168–173 全程为空），
   这样 §5(c) 的矩阵成为可读的偏好声明；同时告诉我 UI 上 `id 1..6` 对应什么（卡位还是训练位），
   我把它钉成语义，用来区分「玩家声明要练」和「影子实际练了」。
3. 可选加固：**同一张 LF 卡（106301，route 93）再开一局**。即使分数不到 LF，也能把
   「LF 卡组 + 手动逐回合」这一类样本从现在的 1 局（179，60,493 那一档）加到 2 局。

**做不到、也不必 asks 的**：
- 已育成高分马的**过程**补不回来——报文里没有赛后逐回合结构（实测 `training_report_info`
  只有 `{season_id, point, is_payment, …}`，见 `210904_0122_notify_response.bin`）。
  72,898 / 71,457 / 41,685 这三张只能再贡献终局快照，而终值已经在 CSV 里了。
- 终值、卡组、技能、赛程、因子这些**不用**用户导出：LF 段 47 张里全有，已落在
  `out/lf_chara_snapshots_20261104.csv`。
