# S7 定价 2×2 实验（revise × pt_favor_rate）— 2026-11-03

一次性壳 `E:/HJM/_s7x2`（**port 工作树的 tar 副本**，非 HEAD：`dist.rs`/`gate.rs`/`mccli.rs`/`state.rs` 在 port 里是未跟踪文件，`git archive` 拿不到，只能用 `tar --exclude=./target --exclude=./.git` 整棵复制）。

## 结论（先说能用的）

1. **`status_score` 缺 `revise` 不是可单独修的缺陷。** 只补 revise（把查表口径改成官方 `table[2v−1200]`）三分量**全部显著更远**，两个种子、两个 PT 档都稳定：五维和 −198~−203、五维分 −1138~−1185、PT −173~−177。
2. **原因：估值层还有第二个错，两个错几乎互相抵消。** `preview_training`（train.rs:43）给的是**未压缩**增量，正式结算才走 `soft_cap_gain`（train.rs:167）。revise 单独加 = 边际价算成官方的 2 倍（超 1200 那段）。**revise + 增量补 `soft_cap_gain`**（= 精确的官方终局分边际价）与不修的现状对照：五维和 −29~−31（显著但极小）、五维分 −16~−40（**无显著差异**）、PT −19~−21。⇒ 口径修正是**中性**的正确性修复，不是分数修复。
3. **`pt_favor_rate` 2.0 → 1.0 是唯一全绿的旋钮，且零代码**（配置覆盖层）。三分量全部**显著更近**，在 revise off / revise+cap 两档、两个种子共 6 组配对里无一例外：五维和 +37~+66、五维分 +560~+784、PT +15~+43。
4. **但这条要到 0.5 还在涨**（off 档：+104/+1212/+73，仍全绿；**已按规范 5 换种子复跑，seed0/1/2 三遍 9/9 同向**）——单调下降的 PT 权重把三分量一起推高，正是「锚点真值在每一格都高于我们所有臂」时的典型signature：**门禁此时量的是「产出更多」，不是「定价更对」**。PT 本身是训练的副产品，压低 PT 价 = 让训练挤掉「只给 PT 的动作」= PT 反而变多。⇒ **别把 favor 扫到很小当成果**；这条证据支持的是「S7 的 PT 追法不划算」，缺口性质仍是**量不够**（与 [[project-paired-gate-method]] 的 PT 结论同向）。

## 建议

- **不并回 revise 单改**（数据否决）。要并就并 **revise + 预览压缩** 这一对，且登记为「口径正确性修复，门禁中性」，与 [[project-stat-cap-wiring]] 同类，不写进分数收益。
- **`pt_favor_rate` 默认 2.0 这条出厂值是错的**，但改成 1.0 的收益**不能当机制证据**（锚点全程偏低）；正解是先补产出量的机制（非训练 PT 来源 / 稽古 PT / 剧本事件收益表，见 [[project-pt-scale-inversion]] 步骤 9），再重扫 PT 权重。
- **`status_weights` 必须一起扫**：revise 的副作用全在跨维分配上，权重不动就下结论会把「定价错」误判成「修口径有害」。
- 壳 `E:/HJM/_s7x2` 用完待删（登记见本文；`_nocap` / `-softcap` / `-rollout` 三具旧壳也还在待删队列）。
