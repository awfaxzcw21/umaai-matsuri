## 0. 判据（跑前先写死）

#56 §4 那句话里混了两件事，所以拆成三条**逐格**残差，各自有独立判法：

| | 残差 | 问的是 |
|---|---|---|
| **R1** | 面板自报 `stat_gains` − `home_info[510x]` 预告 | 面板那条数到底是哪条腿 |
| **R2** | 面板自报 − (home + festa) | #56「面板自报是两者之和」若为真应为 0 |
| **R3** | 实到 − (home + festa) | 两腿恒等式本身（#34 在 PT 上 227/229 那条） |

口径全部沿用现成工具，不新造读法：腿＝`params_inc_dec_info_array` 的 target_type 1..5（10 体力、30 技能Pt），
home 腿取 `home_info.command_info_array[cid]`、演目腿取 `festa_data_set.command_info_array[cid]`
（同 `tools/keiko_curve.py:leg_map` / `tools/keiko_two_leg_identity.py`）。
**阈值**：主结果态下五轴「逐格为 0」的比例 ≥ 95% 判成立；其余按失败手／钳位单列，不摊派。

**pre/post 的坑（第一版踩过，改动已写进脚本 docstring）**：pre 不能用「最后一个带 510x 条目的报文」——
有些重复板包只带条目不带预告（面板把那种行当占位跳过，`live_reader.py:248`），拿它当 pre 会得到
`home=festa=0` 的**假「恒等式成立」**（第一版就是这样，五轴 0 的比例虚高到 89–95% 却全是 0=0+0）。
改法：pre 一律用 `_index.csv` 选定的那块板（＝state 的来源，R1 已逐格证它的 home 腿＝面板自报），
post 只从它**之后**的同 `(run,turn)` 报文里取第一个带 `command_result` 的（窗口不跨回合）。

## 1. R1：面板自报 ≡ home 腿（逐格全等）

303 块 state 板里稽古行 **850 格**（带分身槽 402、不带 448），全部都能在同 `(run,turn)` 的板包里取到 510x 条目。

| 组 | n | 速度 | 耐力 | 力量 | 根性 | 智力 | 体力 | 技能Pt |
|---|---|---|---|---|---|---|---|---|
| 稽古格·不带分身 | 448 | 全 0 | 全 0 | 全 0 | 全 0 | 全 0 | 全 0 | 全 0 |
| 稽古格·带分身 | 402 | 全 0 | 全 0 | 全 0 | 全 0 | 全 0 | 全 0 | 全 0 |

（每格「逐格=0」100.0%、min=max=0，无例外。）

**结构性理由**（一手，不靠统计）：面板 `stat_gains` 只从 `home_info` 那条条目读——
`live_reader.py:249` 在 `for c in home_info.command_info_array` 的循环里做
`stat_gains = {n: params.get(tt, 0) ...}`；`festa_data_set` 在 `pick_state` 里**只**用来填
`predict_gain_act_gauge_array`（gauge），从不进五维。稽古行与普通行走的是**同一段代码**（都按 `command_type==1` 收）。

⇒ **#56 §4「稽古行的面板自报是两者之和」为假**。它把「实到等于两腿之和」（真，见 §2）误读成了「面板自报是两腿之和」。
**后果不是坏结论，是省一步**：稽古行的 `pkt` 本来就是普通训练腿的预告，与 #56 的 DiD 口径同一条腿，**无需拆项**。

## 5. 匹配口径：必须按 cid→应然轴，不能按面板 argmax 标签

面板的 `train` 名是 `_train_name_from_params`（`live_reader.py:134`）＝**五轴里增量最大的那一维**，
不是槽位。一手对照表＝面板自己的 `training.py:37 TRAIN_COMMAND`
（`101 速｜102 力｜103 根｜105 耐｜106 智`；稽古 `5101..5105` 顺位速耐力根智），
与 303 块 state 的 (cid, 各轴收益) 交叉表逐位吻合（101→速度 133/133、103→根性 133/133、105→耐力 133/133、106→智力 133/133、102→力量 114/133）。

**#56 的读数经核没被这个坑碰到**：`out/board_heads_only.tsv` 646 行里 (slot 标签, cid) 交叉表
只有 力量←102 114、耐力←105 133、速度←101 133、根性←103 133、智力←106 133 ⇒ **0 行错配**。
原因是 state 里 commands 的数组顺序是 `101, 105, 102, 103, 106`（逐块板都一样，例：`168_t56`），
`.find(train=="耐力")` 先撞上**真耐力行 105**，所以耐力槽拿到的是正确那一行。
代价是**19 块板的「力量」行静默丢失**（646 行而不是 665）：那 19 块板上 cid 102 那一格主轴被耐力盖过
（例 `168_t56` 的 102 ＝ `{耐力 18, 力量 15}`），标签变成耐力，力量槽就没有行了。稽古行同样有 9/850 格标签≠应然轴（`5101` 标成力量 7 次、`5102` 标成根性 2 次）。
⇒ **第 2 步的取行必须按 cid→应然轴**，顺带把这 19＋9 格找回来。
（这条顺序巧合**只保住 #56 已有行的配对正确性**，不保证换样本后仍成立：它是 `home_info` 的下发顺序，不是我们的约定。）

## 6. 第 2 步的做法（据本步结果改写，与 #56 §5 的原案不同）

#56 §5 的原案是「先拆面板自报，再做 DiD」。本步证伪了前提，所以改成：

1. `pkt` 直接用面板稽古行的 `stat_gains`（＝home 腿，R1 已证）；
2. `eng` 必须是**引擎的 home 腿单独值**，不能是合成稽古预告（§3 的量级证据）——这需要在 `E:/HJM/_wt_clone`
   里把 dump 的取行闸（patch 第 373 行 `&& !is_keiko`）拆掉，并让引擎侧把 home 腿单列；
3. 剂量只该动稽古格那一格：**自检仍是「非分身格三档 `eng` 逐字节相同」＋「普通行的全部读数与
   `board_56.exe` 逐字节相同」**（新增行只能是稽古行）；
4. 分身标记的登记要按**行**而不是按训练位：`state.rs` 那版把 `sub_partner_ids` 按 `train` 名合进
   `clone_marks[t]`，普通行与稽古行会互相串。本样本里这事**没有实际发生**：303 块板逐块数下来
   **只有普通行 133 块／只有稽古行 170 块／两类都有的 0 块**（合宿回合 `home_info` 的五条训练条目就是
   `5101..5105`，非合宿回合只有 `101/102/103/105/106`），所以 #56 没被串到——
   但**第 2 步仍要显式登记这条**（别让它变成隐式假设：换 turn set／换剧本不保证还是 0 块混合板）。

   顺带一条对扩样意义的量化：#56 吃的是 133 块**普通行板**，稽古行全在另外 **170 块板**上（两块集合**不相交**），
   其中 134 块带分身稽古格 ⇒ 第 2 步是**整批新板**，不是老样本的补格。

## 7. 本步没能判的东西

- **根性轴的卡种剂量**：样本里 0 个根性分身卡（§4），换任何档都判不了。
- **力/智的卡种剂量能否与速/耐同式**：本步只登记了覆盖数（110／49），没测——那是第 2 步。
- **体力侧的两腿恒等式**：10/99 手不闭合（全负、集中在末段 73–77），机制未定，本档不解释。
- **R3 只有 100 手**：稽古板每回合只执行一格，100 手来自 134 块带分身稽古板的子集；
  这是「恒等式在真机上是否逐格成立」的样本量，不是 DiD 的样本量（DiD 吃预告，402 格全可用）。
- **`r_state` 的语义**：本档只把它当结果态分层用（2×99／1×1，且那一手实到全 0），
  没有从报文侧证明 2＝成功；判据用的是「实到五轴全 0」这个直接观测，不是状态码。
