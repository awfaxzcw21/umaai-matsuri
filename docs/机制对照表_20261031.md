## 附：已排除的假故障（别再重复怀疑）

这三条被当成 bug 报过，实测都是误报或影响≈0。复现命令都写在下面，别再凭「看起来不对」下结论。

### 甲、`matsuri-dist` 赛程「只排 15 场、少 t76/t78」——**误报，全部覆盖**

`crates/matsuri-cli/src/state.rs:32-46` 的 `schedule_turns()` 确实只留 `RaceMask::MIN_TURN..=MAX_TURN`（**11..=74**，0 基）内的回合，所以 17 场被裁成 15 场。但**终盘三场是 `is_race_turn` 硬编码兜底的**：

```rust
// umaai_next/crates/umasim/src/game/uma.rs:202-208
pub fn is_race_turn(&self, turn: i32) -> bool {
    if turn == 73 || turn == 75 || turn == 77 { true }   // ← 75/77 就是面板 t76/t78
    else { self.career_races.contains_turn(turn) }
}
```

本局实测（`out/live_state.json` + `race_schedule.schedule_from_state`）：

| | 值 |
|---|---|
| 面板赛程（1 基） | 12,23,31,32,34,44,54,56,59,60,66,69,70,72,74,76,78（17 场） |
| → 0 基 | 11,22,30,31,33,43,53,55,58,59,65,68,69,71,73,75,77 |
| mask 11..=74 留下 | 15 场（丢 75、77） |
| `is_race_turn` = mask ∪ {73,75,77} | **17 场，未被覆盖的 = 空** |

→ **不是 bug，不需要改。** 只看 mask 输出会以为少两场，这是两段机制拼起来的（mask 管 11..=74、硬编码管终盘 73/75/77）。

### 乙、「赛程退化 / 解析不出」——**不成立**

`live_state.json` 的 `races` 字段为 0，是因为它只在**面板渲染时**由 `_fill_races` 填。直接调 `race_schedule.schedule_from_state(live_state)` 能解出 17 场，`out/route_ids.json` 里也有 17 个 route id。

判定命令：`python -c "import json,race_schedule as R;print(len(R.schedule_from_state(json.load(open('out/live_state.json',encoding='utf-8')))))"`
