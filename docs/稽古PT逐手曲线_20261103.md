## 4. 假设 ② 裁决：`sp_practice_pct`（effect_type 201）

台账 §3.2 问「教诲 `sp_practice_pct` 该不该再乘进稽古的 PT 腿」。三条证据：

1. **已经接了**：`mod.rs:1323-1328` `sp_bonus = row[5] × (sp_practice_pct+100)/100 − row[5]`，
   门是 `five_types = card_type_count 里 >0 的种类数 ≥ 5`；
   而 `master.mdb` 里 201 那批行的条件是 `condition_type=1, condition_value=5`
   （编成卡类型 ≥5）⇒ **门槛与表逐字一致**，没有接错门。
2. **它是这条曲线的下锚**：Lv1 实测 SP腿比中位 **0.200**，恰等表值 20%（n=19）。
   一个平摊常数不会恰好落在表值的 20% 上 ⇒ 201 这个机制**真实存在且量级对**。
3. **但它补不上高段**：比值/表 在 Lv3+ 稳定跑到 **1.5–2.1 且非单调**（Lv9 2.779 vs Lv10 2.759）。
   201 表在 Lv8→Lv10 是 100→135→170（还在涨），比值却趋平。

⇒ **裁决：接线正确、但不充分。** 高段有一个未解释的额外因子；按规范 3，
没拆到公式前**不许**把「比值/表 ≈ 2」写进 `data/` 或配置。

  {2,3,4,8,13,16,18,20,21,202,203,205,206}，里面唯一与 PT 沾边的是 8 = 研鑽の教え →
  追加稽古发生率；而追加稽古的 SP 是**定值 +20**（上限档），且
  `extra_keiko_rate`/`apply_extra_keiko`（`mod.rs:1054/1080`）**引擎已实现**。

  与演目腿的相关性无定义 ⇒ 不是「槽越满 PT 越多」。
- **人头/上下段不驱动**：同 Lv 内按卡组人头分层，SP腿比没有单调剂量
  （Lv6：0人 1.20 / 1人 1.32 / 2人 1.13；Lv8：0人 1.81 / 1人 2.16 / 2人 1.96），
