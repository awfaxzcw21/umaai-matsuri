# 选位共因检验：「取最满」是真偏好，还是演目需求的影子（2026-11-04）

问题来自 #40（`docs/训练腿预告对账_20261104.md` §3）：真机落子八成落在盘面人头最多的格，
`落子站位/最满位` 真机 0.95 vs 引擎 0.56，于是把人头缺口的**对数份额 65% 记在「选位策略」**。
本条线要拆的怀疑是：这 0.95 可能**只是影子**——支援卡按担当演目站位，玩家挑的是「要补的演目」，
那一格恰好人头最多。若成立，#40 的 65% 虚高，应改记到「站位模型与演目需求对齐」，#42 的杠杆点也跟着换。
数据 = 真机一手报文，全部判据为**条件化**表；不写配置、不落公式、不 commit。

脚本：`tools/train_slot_confound.py`（纯标准库，只读盘上数据）。

## 4. 裁决

**三个候选里选 ①「真偏好人头」。** 三张表同向：

1. 需求格与人头最满格**不是重合而是反相关**——观测重合 48.4% 低于同板置换基线 66.1%，
   两边都唯一时 0/13 命中；需求格人头比同板其余格少 0.64（95% 不含 0，n=33）。
   若「取最满」是「取需求」的影子，这两个数都该是正号。
2. 在**需求集合与人头集合完全不相交**的手上（无从重合），玩家选最满格 78.9%（n=38，CP [62.7, 90.4]，
   p=0.0005）而不是需求格 17.0%，随机基线只有 47.6%。
3. 排除重合层、控制需求缺口后，人头的条件斜率仍然显著（β=+0.853，z 4.51，每 +1 人头赔率 ×2.35），
   需求缺口是**负**的（×0.57）。`R_player = 0.833 > R_rand = 0.600 > R_need = 0.490`。

一句话：**真机玩家不是在补演目缺口，是在往人头多的格挤；越缺的演目那一格反而人越少。**
（这是给定候选集上的选择倾向，属关联层面的判据；没有量玩家估值，所以不断言效用。）

**顺带量到的第二个共因**（#42 要防的）：人头不只与「最满」重合，还堆在**最高 Lv（强项）格**——
高 0.654（n=33），且「取 Lv 最高格」单独就能拿到 `R_lvmax = 0.771`，接近实际落子的 0.833。
⇒ 若 #42 同时加「取最满」和「取强项」两个偏置，这两条腿高度共线，会把同一份增益记两遍。
条件 logit 里控制了 Lv 之后人头仍显著（z 4.51），所以人头是独立的一腿，但**两个旋钮不能各按全额计价**。

## 5. 对 #40「选位策略占 65%」这句话怎么改

- **不被演目需求解释掉 ⇒ 不该把 65% 改记到「站位模型与演目需求对齐」，#40 那个归因方向是对的，不撤。**
- 但有四处必须标注/修正（都在 #40 自己的口径里，不改它的代码）：
  1. **数字要加口径脚注**：#40 §3 的 88.4% 含「候选只 1 格、根本无从选择」的手。稽古层可判手口径下是
     81.7%（含单格）→ **73.6%**（去单格，`heads_own`）；deck 口径 83.2% → 75.8%。
     真实盘面 131 手里 40 手是单格候选。⇒ 幅度系统性偏高 7~10 个百分点（非合宿稽古 88.4% → 78.3%），**方向不变**。
  2. **65% 的对数份额应在「去单格手」的干净指标上重算一遍再定稿**。这件事归 #40 的分子分母，
     用 `tools/train_leg_gap_split.py` 自己跑（本条线不动它）；本页只负责证明**缩小后的份额仍是选位，不是需求**。
  3. **旋钮语义要换**：给策略加的偏置是「同估值下取人头最满（`heads_own`）」，
     **不是**「把演目需求接进选位」——真机 β(缺口) 为负，接需求项会把落子往人少的格推，与观测反着走。
     需求侧如果要做，只能做到**站位排布**那一层（16% 那一段），不是选位那一层。
  4. 新增风险登记：人头 × 强项 Lv 共线（§4 末），#42 定价时两条腿不能各按全额。

## 6. 局限（读数前先看好）

- **n 小**：6 个 run、窗口内 180 手、可判手 140（稽古 91 / 普通 49）；干净对照只剩 38 / 21 手，
  条件曲线只剩 27 手。区间都是宽的（选最满 78.9% 的 CP 区间跨 27 个百分点）。
- **观察性、非干预**：候选集由盘面给定，玩家也在选演目路线 ⇒ 拆的是共因方向，不是「人头导致得分」。
- **需求判据有两个自由度**：第 4 场 need = 6 是夹逼值不是 master.mdb 行；「平手取达标记数最少」是本页的
  tie-break 约定。两者都做了敏感性（`--need-key level`），结论不变。
- **普通层带假设**：位↔演目按中位主轴近似（引擎的槽落在担当演目，`mod.rs:1211`）；
  主判据取 1:1 的稽古层。普通层的缺口系数在控制后已不显著（z −1.82）。
- **条件 logit 只有两根解释轴**，未建模卡等级/友情/bonus 条等第三因，且有 IIA 假设；
  McFadden 手内似然消掉截距与手效应，代价是不能报绝对效用。
- **窗口只覆盖 t30–78**（合宿与之后），t1–29 与 t79+ 未测；普通层没有合宿样本。
- 置换零假设固定板结构、只随机化演目标签 ⇒ 检验的是「人头分布是否与演目无关」，不是得分好坏。
