# 骏大祭剧本事实层（2026-11-03）

> 机读版：`docs/剧本事实表_20261103.json`（同内容、带字段）。本文件是人读索引。
> 用途：给「只读代码、不看报文」的决策侧（含另一条线的 AI）一份能直接引用的数值语义表。
> **这是事实层，不是口径层** —— `data/*.json` 才是 sim 真正加载的那一份；两者不一致时，看下表「来源等级」判断谁更可信。

## 先记住三句（这三条错法会直接把数值算歪）

| 编号 | 错法 | 正确 |
|---|---|---|
| **M1** | 「速度到 2200 后收益归零，所以后期要糊副属性」 | 2200/1850/1800/1700/1800 是**初始上限**，可被卡组 + 发表会继续抬高，真归零在**硬顶 2500**。后期速度涨得慢的原因是 F2 软上限 + 接近上限截断，不是 2200 归零。 |
| **M2** | 「属性超过 1200 就整条收益减半」 | 减半只作用于**增量中落在 1200 以上那一段**，向下取整：`below = min(gain, max(1200−pre,0))`，实得 = `below + ⌊(gain−below)/2⌋`。pre=1195 / 增量 30 → **17**（不是 15）。 |
| **M3** | 「减半只管训练，事件/赛后再算」 | 判据是**这条机制写不写五维**，不是机制名。凡写五维都过同一个 `soft_cap_gain`：训练 / 稽古 home 腿 / 赛后 / 演目平摊 / festa。PT、体力、% 类 buff 不吃。 |

## 十条事实

### F1 五维上限体系
- 初始上限 **2200 / 1850 / 1800 / 1700 / 1800** = `1200(default_max) + 剧本加成(速1000 耐650 力600 根500 智600)`；再 + 卡组开局抬升 + 大祭发表会抬升；**硬顶 2500**。
- 上限是**截断**不是乘子。机制包里另有一组 2150/1800/1700/1700/1800，属另一层口径，不可混用。
- ⚠️ **来源等级 = 文档层（official + memo 一致），这五组数字不在我们 `data/` 里**。代码侧只有引擎 per-uma `five_status_limit_base`；`data/scenario_matsuri.json` 里唯一与上限沾边的是 `act_level_effects` 的 `sp_limit`（Lv4 起非零，Lv9/10=120）与 `base_limit`（Lv9=20 / Lv10=25），**档位语义未钉死（#16），不许拿它反推初始上限**。
- 证据：`docs/mechanism.md:406`、`docs/LF靶子_20261103.md:42,44`、`docs/glossary.md:169,213,262`、`crates/matsuri-core/src/game/mod.rs:319`。

### F2 1200 属性软上限
- 公式见 M2。只对正增量生效，`cap<=0` 关闭，向下取整；pre ≥ 1200 时整条折半（7→3）。
- 报文依据：`chara_info.default_max_*` 各局恒 1200；实测 cid168 t76（1195/30→17）、t54（1300/7→3）。
- ⚠️ 同文件里还有 `cap_decay: 0.0` / `cap_decay_floor: 0.15` —— 那是**另一种建模**（按剩余空间打折），出厂 decay=0 表示走软上限这条路。别以为 decay 也在生效，更别两者并用（会双重压低五维）。
- 证据：`data/scenario_matsuri.json:521-523`、`game/mod.rs:1674-1687` + 断言 `:1734-1750`、`:2013-2020`；调用点 `:474,492,604-608,812,1360-1364,1519`。

### F3 五维 → 官方分
- `官方五维分 = Σ five_status_final_score[revise(v)]`，`revise(v) = 2v−1200 (v>1200)`。表长 3,802、末档 23,905，`T[3800]=T[3801]` ⇒ **显示值 2500 起真实边际 = 0**。
- 表是**折线**，每点边际随水平变化。锚点 run179/cid179 `[1998,1470,1656,1344,1573]`（和 8,041）→ 五维分 **42,201**，132,000 局零失败复现。
- ⚠️ 估值层现状是**直接拿 raw 查表、不套 revise** —— 那是引擎现状不是官方口径。不套 revise 会低估高属性轴，低估倍数随水平走：1300 段 ×2.19 / 2000 段 ×2.82 / 2500 段 ×0.00。**不许当常数抄进配置**。
- 证据：`data/constants.json`、`tools/revise_pricing_gap.py`（**必须从仓根跑**）、`tools/ga_r2_pricing_gap_20261103.py`、`tools/weights_vs_multiplier_20261103.py`、`docs/上游并档对账_20261103.md` §5。

### F4 PT
- `pt_score_rate = 2.0`（固定，不是旋钮）；终局把剩余 PT 折成技能评分，官方约 **2.46/PT**（引擎已计 2.0，终局再补 0.46，上限 45,000）。**PT 不吃 1200 软上限**。
- 决策层的 `pt_favor_rate` 是另一码事：让决策按 `2.0 × favor` 分/PT 计价（双乘槽），**只改取舍权重，不改产出**。实测 favor=1.7271 只填补五维:PT 混合比缺口的约 8.2%。
- PT 偏少的缺口在「非训练 PT 的量」，不在汇率。
- 证据：`data/constants.json:5`、`game/mod.rs:1626-1632`、`:1695`、`tools/pt_favor_double_count_20261103.py`、`docs/PT台账_20261103.md`。

### F5 赛后奖励（二段式乘区）
- `实得 = floor( floor(base × m_card) × m_cp )`，`m_card = (100 + 支援卡「赛后」)/100`，`m_cp = 1 + 发表会 cp204`；**然后还要过 F2 软上限**。
- 基准值：目标赛（生涯赛）五维各 **+5** / PT **+72**；URA 予選 / 準決勝 / 決勝 = **+10** / PT **40 / 60 / 80**；目标外 **GI** = 随机一项 **+10** / PT **+45**；**GIII** = 随机一项 +8 / PT +35；**GII = null（无干净样本，未知不是「与目标赛同」）**。
- 「1 随机项」是真随机：两个真机样本分别落在耐力与智力。
- 自选比赛窗口：面板 45 / 69 ⇒ **引擎 44 / 68**，各 3 场、全 G1、需 **12,000 粉**（引擎无粉丝系统 ⇒ 未建模；真机体力代价 −15/−20 也未建模）。
- ⚠️ `data/events.json` 的 `race_career = [7,7,7,7,7,67]` 是**通用引擎默认**，本剧本路径会逐格覆盖五维与 PT（同一段里 `vital` 之类仍取自行本身）。固有事件的变体值是事件分支，不是赛事常数表。
- ⚠️ 同文件另有 `race_g1 [3×5,50]` / `race_g2 [2,3,2,3,2,40]` / `race_g3 [2×5,35]` / `race_g4 [1,2,1,2,1,25]`（含 `vital −15/−5/−20` 分支）—— 这些也是**通用泛用行，我们的 `do_free_race` 一行都不读**（走 `race_reward.non_target`）。**别把 `race_g2` 的 +40 当成 GII 的答案**，GII 仍是无干净样本。
- ⚠️ 我们 `data/events.json` 的 `system_events` 里**没有** `race_ura_qualifier/semifinal/final` 三行（上游与通用引擎有）。引擎 `push_race_event` 在 t73/75/77 找不到这三行时会**静默回退 `race_career` 并打一条 diag** ⇒ 合并后若走引擎那条路，URA 会拿到 `[7,7,7,7,7,67]` 而不是 `+10 / 40·60·80`。
- 证据：`data/scenario_matsuri.json:504-520`、`game/mod.rs:1670-1672`、`:1505-1532`、`:456-484`（`do_free_race` 走 `non_target`、不读 `race_g1`）、`game/traits.rs:95-110`。

### F6 稽古 = 两条腿
- 恒等式：**稽古实到 = 同一训练位的普通训练结算 + 稽古板自报演目加项**（229 手执行稽古里 **227 手五轴全中**）。home 腿就是 `training_leg`，两处共用同一条公式。
- **分腿折**：报文里两腿各自已套过软上限 ⇒ 分腿折再相加，不是相加后折一次。
- 演目平摊（Lv1 `all_base = 10`）是**非主属性**固定加项，在乘区**之后**相加、再进软上限；主属性不吃，平摊不进乘区。
- 失败分支未建模（未定）。
- 证据：`game/mod.rs:508-520`、`:1340-1346`、`:1357-1358`、`:2028`、`:2099-2104`；`docs/festa平摊加项_20261103.md`、`tools/keiko_two_leg_identity.py`。

### F7 得意率 = 落位概率，不是效果乘数
- 官方语义：得意率决定训练位**落到哪一格（概率）**，不是把该格效果乘上去。
- ⚠️ **我们引擎没有落位概率模型，`deyilv` 仍是占位**，暂按「训练效果%」近似 —— 近似，不是结论。任何「得意率高 ⇒ 收益高」的估值都建立在这个占位上。
- 证据：`data.rs:298-302`、`game/mod.rs:39-40`、`:220-221`。

### F8 教诲 / 転成 / 発表会
- 教诲发放 `advice_grant_turns = [2]`；転成发放 turn **23** → 601/701，turn **47** → 801/901/1001。転成后基础教诲的等级效果**整条换成** `fusion_effects` 固定档，新教诲效果再叠加其上。
- **発表会 permanent buff 是累计总量，不是增量 ⇒ 设值（=）不能再累加（+=）**。`gain_pct`（得意率 type 4）/ `friend_pct`（友情 type 202）/ `hint_pct`（提示 type 2）各自独立；引擎无提示/技能模型 ⇒ `hint_pct` 只记录、不参与估值。
- 证据：`data/scenario_matsuri.json:{advice_grant_turns,fusion_grants,check_points,act_level_effects}`、`game/mod.rs:210-224`。

### F9 每回合收益表
- 一手来源 = home 预告 + festa 预告（**281 / 287 逐轴全等**）；预告值**不随剩余空间衰减**；287 那手钳位实测零触发。
- 收益表给的是**打折前**的量。到账链条：收益表 → 乘区（教诲/彩圈/友情）→ 加平摊（非主属性）→ 套 1200 软上限 → 与当前值比上限截断。**跳过任一层都会得出「后期速度很赚」或「速度归零」这种两端都错的结论。**
- 证据：`docs/每回合收益表_20261103.md`、`data/scenario_matsuri.json:{training_basic_value,keiko_basic_value,keiko_basic_value_late}`。

### F10 自由比赛（马娘义务）≠ 自选比赛窗口
- **义务**（`umaDB.freeRaces`，玉藻 cid102102）：t12-28 需 1 场；t29-48 需 4 场且 grade ≤ 3 —— 完不成会打死育成。
- **窗口**（玩家可主动报名）：引擎 44 / 68 各 3 场全 G1，需 12,000 粉（见 F5）。
- 两套语义不同层。上游并入的那份把义务做成硬门槛，我们侧候选生成里只有窗口 ⇒ **合并时必须补 Race 候选（#25）**。
- 证据：`docs/上游并档对账_20261103.md` §3、`game/traits.rs:95-110`、`data/scenario_matsuri.json:517-520`。
