## 1. CRN 对比方法

- 两个入口都叫 `matsuri`，都用 `build_game`（turn 0）+ `Runner` + **`RandomTrainer`（共享引擎 umaai_next 里同一份代码）**，跑满 78 回合。
- 用 cwd overlay `ai_config.toml` 把两仓的**卡组对齐成同一套** `[303174, 303114, 303004, 303224, 303204, 303234]`、种子对齐 0..29。
- 只剩「剧本 config（scenario_matsuri.json + matsuri_config.toml）+ game 代码」是两仓各自的一份 —— 这正是要量的分歧。
- `random` 训练员 = 共享代码，所以隔离掉「训练员差异」，只量**剧本机制 + 事件管线 + 结算**的分歧。

## 3. 归因（与交接包 §6.3 P0 对得上，不另证）

PT 系统性低 ~1900、五维和低 ~404，方向与我们已经记录的缺口一致：
- **転成占位**：我们仍是 `if turn==23 { gain_pct += 0.25 }` 占位，上游 `matsuri_config.toml` 有完整 `[[fusion.year2]]/[[fusion.year3]]`（5 组配对）+ `.with_config()` 注入。
- **PT −29.1% 缺口**（交接包 §6.3）：発表会粉丝/理事长/负责人/灵感、教诲按人头叠加、赛后奖励分表——上游已写进 config + 测试，我们没做完。
- **属性压缩口径冲突**（§4 直接冲突）：上游「计分原始值、显示减半」，我们真机「增量减半(>1200 部分减半向下取整)」。

## 4. 初步结论（选边建议，非定案）

- 两引擎**系统性分歧，PT 尤其大（~1900 / ~35%）**。这排除了「port 是零成本的免费午餐」——A 不是白拿。
- 但分歧方向是**我们缺、上游有**：上游 PT 更接近真机（我们 −29.1% 缺口），还自带 2124 行机制测试 + 打分函数 + view 快照 + 落位/人头/URA 口径。
- ⇒ **倾向 A（以上游为新基线 port）**，代价 = 把我们的 §6.2 真机修正（属性压缩增量减半、失败口径、演目槽、転成配对、目标赛一包 +19/+128、追加稽古三选项、训练 Lv 每4次+1……）逐条压回上游 schema，并**真机裁决「属性压缩」这一条硬冲突**（上游是错的）。
- 尚缺的「量」：① PT 差逐机制归因（転成 vs 教诲 vs 発表会 vs 赛后奖励各占多少）；② `matsuri` 训练员（真实档，高属性）下的端到端差（`random` 只到 5000 档，属性压缩>1200 的高档效应没完全显现）。

## 6. PT 差逐回合归因（5 种子均值，脚本 tools/pt_trace.sh，数据 docs/pt_trace_5seeds.tsv）

同种子同卡组跑满 78 回合，逐回合对齐两仓 PT，看差在哪几个点跳出来。差值 = 上游 − 我们（我们低为正）。

- **两个离散跳变点，正好是転成**：
  - t22→t23：delta 从 160 跳到 **270**（+110）——第 1 次転成（year2→year3）。
  - t46→t47：delta 从 592 跳到 **739**（+147）——第 2 次転成（year3→year4）。
  - 两跳合计 ~250 PT，只占 1698 总差的 ~13%。我们転成仍是 `if turn==23 {gain_pct+=0.25}` 占位（只 fire 一次、是百分比不是 PT、且 turn47 完全不 fire），上游有完整 `[[fusion.year2]]/[[fusion.year3]]`。
- **其余 ~87% 是全程匀速累积**（非单点）：斜率从早期 ~+8/turn 升到末期 ~+32/turn，随属性/粉丝增长而放大——对应交接包 P0 的连续缺口：教诲按人头叠加、発表会粉丝/理事长/负责人/灵感、训练 PT 口径、赛后奖励分表。
- **另见 §5 手核**：上游 T77 行 ≠ 终局盒（终局多 +15×5/+150 PT 的赛后结算），我们 T77 行 = 终局盒（无这笔）。

⇒ **归因结论**：PT 差不是「缺一个事件」，而是「転成(13%) + 一整套 PT 管线全程少算(87%)」的复合缺口。逐点补（选 B 摘思想）要动十几个机制点；以上游为基线（选 A）则这些都在 + 有测试覆盖，代价集中在「属性压缩」一条硬冲突 + 把 §6.2 真机修正压回。
