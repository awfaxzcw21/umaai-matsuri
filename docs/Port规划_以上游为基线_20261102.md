## 3. 移植清单（我们要带过去的东西）

### 3a. cli 资产（面板数据链的命脉，必须完整 port）
- `crates/matsuri-cli/src/state.rs`（372 行）：报文 state.json → `assemble_game` 覆盖 turn0。
- `crates/matsuri-cli/src/dist.rs`（343 行）：`fork_for_rollout` + `run_full_game(&MatsuriRolloutTrainer)` + gate 输出。
- `crates/matsuri-cli/src/gate.rs` + `mccli.rs`。
- **关键风险**：这些直接依赖我们 `MatsuriGame` 的字段/方法签名，上游 `MatsuriGame` 结构不同（含 ActLedger/AdviceLedger/with_config 等），`assemble_game` 和 `run_full_game` 必须重接到上游 `view()->MatsuriView` 接缝上。这是 port 工作量最大的一块。

### 3a.1 seam 精确映射（本轮实测，state.rs/dist.rs 接上游 API 的断点清单）

**共享引擎 `umaai_next`（两仓同一个 checkout，`E:/HJM/umaai_next`）提供且不变**：`Game`/`BaseGame`/`RandomTrainer`/`FlatSearchGame`/`Config`/`Data`/`RaceMask`/`run_full_game`/`search_score`。差异全在 matsuri-core/matsuri-cli 两层。

| 我们的接口（state.rs/dist.rs 依赖） | 上游对应 | 断点级别 |
|---|---|---|
| `build_game_for_uma(cfg, data, uma_id)` | 无此函数；`MatsuriGame::newgame(uma_id, deck_ids, inherit, race_grades, data)` 直取 uma_id，或 `build_game(cfg, data)` 走 `cfg.sim.uma` | 改写 |
| `Game::Person = BasePerson`（引擎类型） | `Game::Person = MatsuriPerson`（剧本类型，包 `base: BasePerson` + `origin: PersonOrigin` + `act` + `avail_turn` 等） | 改写 |
| `add_person(BasePerson)` | `add_person(MatsuriPerson)` | 改写 |
| `game.act_level[i]` / `game.act_gauge[i]`（裸数组） | `game.acts.level[i]` / `game.acts.gauge[i]`（`ActLedger` 结构） | 字段改名 |
| `game.advice_base[i]`（裸数组） | `game.advice.slots[i]`（`AdviceLedger`）+ `game.advice.fused[i]` | 字段改名 |
| `game.act_level_cap`（字段） | `game.act_level_cap()`（方法，取 `data.rules.act_level_max_with_friend`） | 字段→方法 |
| `game.train_stat_anchor[t][i]` | 需查上游 view/BaseGame 是否有等价（待确认） | 待查 |
| `game.capture_initial_shining()` | 上游无此方法（待确认等价物） | 待查 |
| `FlatSearchGame::RolloutTrainer = MatsuriRolloutTrainer`（我们自定义 rollout 策） | `FlatSearchGame::RolloutTrainer = RandomTrainer`（引擎）；上游另有 `MatsuriTrainer`（S7 手写训练员=守门链+打分表，是 `matsuri` bin 默认） | 策略替换 |
| `game.gain_pct`（我们転成占位字段） | 上游无此字段（転成已走 `advice.rs apply_fusion_pairs`） | 删除 |

**rollout 策略决策点（关键）**：我们 dist.rs 用 `MatsuriRolloutTrainer`（自写 rollout 策），上游无对应物。可选：
1. 用上游 `MatsuriTrainer`（S7，质量最高、与上游 `matsuri` bin 同口径）做面板 rollout；
2. 用引擎 `RandomTrainer`（CRN 随机基线，仅供机制对拍）；
3. 移植我们 `MatsuriRolloutTrainer`（保留原面板策略，但多一份维护）。
**建议默认 1**（面板要估「好策略下的终局」，S7 最贴近真机玩家），把 2 留作 CRN 对拍工具。此决策影响 gate 数值，需用户点头。

**结论**：state.rs（372 行）与 dist.rs（343 行）不是复制，是按上表逐条改写接上游 API；`base.*` 字段（`deck`/`distribution`/`turn`/`uma`/`train_level_count`）经 `Deref<BaseGame>` 仍可直达，是最稳的一层。

## 5. 风险点

- **接缝风险**：`assemble_game`/`run_full_game` 对 `MatsuriGame` 内部结构的依赖最脆，上游拆了 14 模块 + 加了 ledger 字段，可能需要适配层。
- **属性压缩**：真机口径若与上游「显示减半」冲突，改上游 `train.rs`/`view.rs` 会影响打分函数，要连带校准。
- **不打折**：port 过程中任何一步 PT/五维偏离真机，都要回退定位，不许用系数凑平。
