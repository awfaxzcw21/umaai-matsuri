## 1. 口径（全部先写死再跑，跑完没动过）

1. **决策板** ＝ 同一 `(run,turn)` 里最后一条 `chara_info.playing_state==1` 的板报文（优先不带
   `data.command_result` 的那条）。759 个唯一 `(run,turn)` 里 756 个确实是 ps==1，3 个回退到别的 ps。
2. **可见** ＝ 该 `(run,turn,卡)` 上 `sub_command_partner_array` 命中该站位的条目数 ≥ 1。
   **主单元** ＝ 带 801 来源 **且** 该卡在决策板上确有站位 的卡回合（477 个）。
3. **完全分开** ＝ 某候选变量在 0 槽组与 ≥1 槽组的取值集合交集为空且 0 例外；高基数变量
   （回合号／计数／id／金额）不参与判定；两组样本各 ≥3 才允许下结论。
   本报告另列一种**单侧 0 例外**（必要条件：不可见全部落在同一档），它不是机制，但能定边界。
4. 数值候选按先写死的粗档分层（体力 0／1–30／31–60／61–107／108；heads 0／1–5／6–10／11＋；动机 1–5 原值）。
5. 两特征交叉只在「单特征已把样本切成两块」之后各查一次（§E2）。
6. 「当回合是否比赛／做了什么」两侧都取：响应侧 `t_race` ＝ 该 `(run,turn)` 任一包
   `chara_info.race_program_id ≠ 0`；请求侧 `t_train`／`t_rest` ＝ `single_mode_exec_command_request_common.command_type`
   为 1／3 且请求体 `current_turn` == 本回合。回合级：比赛 282、练了 375、两者都无 109。
7. **反口径检验**（新增）：每张卡另记 `n_slot_any_ps1` ＝ 同一 `(run,turn)` **所有** ps==1 板上该卡
   槽数的最大值。37 例不可见里 **0 行**是「另一块板给了槽」⇒ 不可见不是「取了哪块板」造成的。

> 更正记录：#47 的 §7-3 是在「当回合是否比赛」全 0 的情况下写的。那是 `walk()` 输出元组下标读错
> （读 `x[4]`＝`data` 而不是 `x[5]`＝`chara_info`）造成的 bug，本脚本已修。修完之后 282／759 回合
> 判为有比赛，§7-3 的缺口才有下面的重新定性。**任何引用「比赛回合样本为 0」的旧结论都作废。**

## 4. 为什么比赛回合的不可见不该当机制写

同一回合、同一个比赛，不同 run 的板给出相反结论（报告 §I）：

- t60：10 个 run 全部比赛，run179 的两张 801 卡在板上且 0 槽；run201–204 的在板上且 1 槽；
  run168–172 的卡根本不在板上。
- t66：run179（heads 16，rpi 85）0 槽；run201（heads 14，rpi 75）1 槽。

且 `heads_sum` 不是原因（同层双向都无反例）：比赛且 heads≥17 的 24 卡回合 **24 全可见**；
非比赛且 heads<17 的 44 卡回合 **44 全可见**。

⇒ 比赛回合的 ps==1 板是退化／残留板，它的分身字段不可信；把它写成规则就是拿噪声当机制。

## 6. 奇偶（#47 §7-2）：不可分，且接线不需要分

末段 96 个 801 在板卡回合，三个变量的分组方式完全同向：

| 分组 | 1 槽 | 2 槽 |
| --- | --- | --- |
| 当回合是否比赛 | 48（比赛） | 48（没比赛） |
| 表侧 `race_entry_type` | 48（==1） | 48（==0） |
| 当回合是否练了 | 48（没练） | 48（练了） |

能不能用反例把它们分开：**0 个 `(run,turn)`**。理由在数据里是硬的：

- 全量 759 回合里，`race_entry_type==0` 的回合**从未**出现比赛（0 反例）⇒ 表侧这一档就是「本回合不能参赛」；
- 末段 t74／76／78（`entry==1`）**9 个 run 全部比赛**，t73／75／77（`entry==0`）**9 个 run 全部训练**。

⇒ 这份报文里没有「`entry==0` 却去比赛」或「`entry==1` 却不比赛」的反事实，**因而上不了因果结论**。
但接线不需要判因果：`race_entry_type` 和回合号都是决策时点已知的确定量，且两种口径在末段
逐 run 网格（§G）里给出**完全相同**的 96 个样本划分。

## 7. 可以写进配置的 / 不可以写的

**可以（一手 0 例外，且都是决策时点可推的量）**

- 801 协助教诲卡 ⇒ 在训练回合的板上、该卡自己的站位上给 **1 个分身**（非比赛回合 264／264）。
- 末段（t73–78，`single_mode_turn` 的 `period==3`）**且该回合 `race_entry_type==0`** ⇒ 上面那张卡
  给 **2 个**（48／48）。写成「末段奇数回合 +1」和写成「末段且当回合不比赛 +1」在这份数据里等价。
- 落位仍沿用 #47 已定的四条 0 反例约束：只落在自己卡组位的槽、`sub ⊆ partners`、
  不与本体同训练种、不落自己担当演目的 510x。

**不可以写（写了就是拟合或把噪声当机制）**

- 任何「比赛回合也不出分身」的条件：比赛回合的板不是训练板，方向都不自洽（§4）。
- 合宿牵绊融合 +1、末段 id4 单独作用时的可见率：各有 4／5 条例外定不住（§3）。
  合宿那条尤其像「表侧归属≠实际生效」，需要另一手数据（或 so 反汇编）才允许接线。
- 「体力／动机／彩圈／演目 state 决定分身可见」：§F 的分层可见率只是形状
  （例如彩圈 0 档 100%／1 档 88.36%），两组取值有交集，没有一条达到 0 例外。

**接线建议：可以接 801 这一条线**（训练回合 1 槽 ＋ 末段 `entry==0` 叠加第 2 槽），
其余两个来源先留占位、不进分数模型。前置条件只剩一个待查项：**7 个「同一回合既比赛又练了」
的回合**（疑似比赛后用续跑再练一手：169@48、179@35、179@59、202@30、202@33、203@35、203@38），
其中落在 801 卡在板上的只有 2 个卡回合，且这 2 个都不可见 —— n<3，不满足口径 3c，
所以按「样本太薄」登记，不据此改规则；如果这类回合在实机上常见，需要单独定它。

## 8. 一句话给下一手

要真正定死「比赛回合的板到底显不显示分身」，缺的不是更多字段而是**更多反事实**：
一批在 `race_entry_type==1` 回合**不比赛**、或在 `race_entry_type==0` 回合**强行比赛**的报文。
现有 13 局里没有这种局（§6 的 0 反例），所以这份数据到此为止。
