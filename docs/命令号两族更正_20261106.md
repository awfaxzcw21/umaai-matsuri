## 2 撤回二：「稽古在顶栏是拿不到的」——**结论对，原因错**

现象（一手，影子日志 43 行）：

```
live 非空 31 行；其中出现过「稽古」字样的：0 行
MCTS plan 里含稽古的行：22 行
顶栏真显示（live[0]）：纯训练 31 / 31
```

原因不是「live 里没有稽古条目」，而是 **`mccli.rs:326` 把每条 live 候选一律格式化成
`format!("训练 {name}")`，完全不看 `is_keiko`**：

```rust
live.push((format!("训练 {name}"), val));   // ← 稽古条目也被写成「训练 速度」
```

⇒ 稽古条目**在 live 里是有的，但被贴成了普通训练的标签**，所以：
1. 屏幕上永远读不出「这一手是稽古（吃 gauge、给 Lv+1）」；
2. 我上一次做动作大类统计时，也无法从标签把它们分出来——
   只有当面板规则线写「训练 稽古·根性」而引擎写「训练 根性」时，才露出过一次马脚。

⇒ 这条改判把 #76 从「显示层缺候选」降级为**「显示层缺标签」**——
修法也因此便宜得多：`mccli.rs` 那一行按 `is_keiko` 出「稽古 X」标签即可，
不需要给 live 补候选、不需要新汇率、不需要动引擎。
