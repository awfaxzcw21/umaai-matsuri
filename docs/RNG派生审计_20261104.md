## 1. 判读（先给结论）

**就「臂间跨回合错位、污染配对门禁」这一致命项：A 类缺陷 = 0。**

结构原因（都是本仓自己的代码，不是上游）：

| 事实 | 位置 |
|:--|:--|
| 每进入一个回合，两条引擎流＋剧本自持的策略流**一起重新派生** | `crates/matsuri-core/src/game/traits.rs:58-59`（`next()` 里 `reset_rule_streams()` + `reset_strategy_stream()`） |
| 三条流按 `(master, turn)` 派生，`master` 由 `fork_for_rollout(seed)` → `set_rule_master` 注入 | `traits.rs:41-44`；底座 `E:/HJM/umaai_next/crates/umasim/src/game/base/mod.rs:102`/`:110`、`base/basic.rs:299`/`:325-326` |
| 取流—放回成对执行，中途出错也先放回 | `traits.rs:69`/`:75-76` |
| 类型隔离：局面／事件／回合固定／策略／决策各走各的流，互不污染 | `run_stage` 签名 + `lib.rs:17` 注释 |

⇒ **训练失败判定这类环境随机永远是「当回合策略流的第 0 抽」**，与前一回合消耗了几次无关。
`rng.rs` 自述「只隔离下游、隔离不了上游」这句话对我们**成立的只是同回合内**，跨回合被复位消解了。

⚠️ 这**不是**说门禁免检：CRN 的前提仍是「同 exe ＋ 同 `MC_SEED` / `MC_N`」（`matsuri-cli/src/dist.rs:115-117` 的种子散列），
换 exe／换 config 仍要按 AGENTS.md 那条先重放定标。

## 3. A 类·需要修

**跨回合错位这一项：没有。** 残余两条属「低优先、需一手量化才谈修」：

1. `mod.rs:707/759/775`（及 `:1408/1467/1482`）——**同回合内**失败分支／短路造成的条件消耗位移。
   只把同回合的后随策略点推后，下回合即复位；影响分量＝该回合的五维／PT（掉属性腿、追加稽古腿）。
2. `traits.rs:153/167`——事件历史（`self.events` 计数）驱动 `available`／池大小 ⇒ 同回合事件流位移。
   这是底座自述「隔离不了上游」的固有耦合；影响分量＝事件带进来的五维／PT／体力。

⇒ 两者都**不会跨回合、不会串流**。要不要在门禁里规避，取决于下面的方差量级，不取决于读码判断。

## 4. B 类·已正确（覆盖面）

策略流全部（`387`/`528`/`700`/`1402`）、事件流（`136`/`153-173`、隐藏事件 `1539/1543`）、
回合固定流（`1616/1617`）＝ 按 `(master, turn, tag)` 派生且每回合复位；无 rng 的落位／教诲／赛后表值腿；
harness 侧每样本 seed 派生与每节点新建流＝位置无关。

## 5. 判不了的（缺什么一手，不猜）

| 项 | 缺的一手 |
|:--|:--|
| 「待测」四条对三分量的**实际方差贡献** | 逐回合、同种子、双臂的 trace dump（每条流的 `(turn, counter)` ＋命中的事件 id），比对同 seed 下的差异。纯静态读码给不出量级 |
| 门禁 dump 的**配对前提是否真成立** | `_gate_*.json` 的历史 provenance（是否同 `MC_N` ＋同 `MC_SEED` 生成）——读码只能声明前提（`gate.rs`），验不了历史文件 |
| 跨仓调用方是否也按回合复位 | 已核 `umaai_next/crates/umaai/src/session.rs:270` 实时会话的 EventRng 同样按 `(master, turn)` 派生（一致）；但**线上协议帧驱动路径**与 sim 路径是否等价，缺报文级对账 |
| `dist.rs:119` 决策流 | 现状零风险；属**设计约束**（今后接随机策略／搜索训练员时必须按回合派生），不是当前缺陷 |

## 7. 一句话给门禁

外部那条「先修派生再谈门禁」的顾虑**对我们不适用**：派生已经按 `(master, turn, tag)` 做完了。
我们该盯的是**同回合内的条件消耗位移**——而它的量级必须用逐回合 trace dump 来量，读码判不了。
