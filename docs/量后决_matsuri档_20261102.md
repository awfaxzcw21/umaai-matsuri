原因直白：random 档五维最高 ~1,300，离最紧的那维上限（根性 1,700）还远 ⇒ 钳位从没触发。
⇒ **§1 的机制差 −404 / −1,898 与上限口径无关**，这条线索在低档被排除，别再去那儿找缺口。

### 11.2 rollout 档：效应真实但量级小

### 11.3 判读

- **不能解释与上游的差**：−157.2 只占 §8 五维和差 −2,183.5 的 **7.2%**，−65.6 只占 PT 差 −5,086.5 的 **1.3%**。高档的缺口大头仍然在别处（决策层质量 + 尚未裁决的 >1200 增量/计分口径）。
- **对上游比值反而更远离**：五维和 0.748 → **0.730**。这**不是**接线错了的证据——上游自己也没接（§9 第 2 条），两边都拿着通用 3,100 上限时才「互相接近」。门禁靶应当是真机，不是上游。
- **对真机靶**：接线后 0.788 / 0.703 / 0.465（接线前 0.808 / 0.727 / 0.473）⇒ 我们离靶**更远了 2 个百分点**。按铁律这条**留档不定论**：接线本身有报文一手依据（真机 t30 `stat_caps` 就是 2225/1850/1848/1700/1816），但「离靶更远」提示我们**另有地方把属性算少了**（候选：训练次数 21~30 vs 真机 34 那条已知差、以及还没实测的「训练/稽古增量是否也走 1200 软上限」）。
- **结论**：这条是**正确性修复**，不是缺口的解释项。值得并回主线（让后续所有高档测量都在真机口径上跑），但不要指望它缩小与上游的端到端差。

### 12.3 判读

1. **§11 待办 ② 定案并划掉**：「训练/稽古增量是否也走 1200 软上限（现在只接在赛后奖励上）」——**前提就是错的**，训练早就走了（步骤 3 报文实证），稽古/自选比赛同规则，本轮补了用例。压缩不是「还没接」，是**已经接满**。
2. **压缩不是那个「算少了」的洞**：关掉压缩对真机靶（8,041 / 42,201 / 8,339）的比值只从 0.808 / 0.727 抬到 **0.857 / 0.773**，五维和仍差靶 **−1,152（−14.3%）**。也就是说这条口径最多回收离靶缺口的 **26%（五维和）/ 17%（五维分）**，剩下的在别处 ⇒ 候选只剩 **① 引擎训练次数 21~30 vs 真机 34** 和**结算 = 预览大数 + 橙粉徽章**那条未接的锚点。
3. **「上游无压缩 ⇒ 它五维分超靶 27.5%」这个候选被否**：关压缩后我们与上游五维分和的差只从 −2,183.5 收到 −1,788.0、五维分从 −23,149.0 收到 −21,181.3（补 18% / 8.5%）。§4 那条**计分口径**（上游计分用原始值、显示才减半）才是主因方向，压缩是二阶项。
4. **port 风险（要做的事）**：上游 `crates/` 全仓没有 `soft_cap` 字段 ⇒ 走 A 之后这 −395.5 / −1,967.7 会**凭空消失**，门禁数字与本轮不可比，而且消失方向是「变高」，容易被误读成「上游更接近靶」。⇒ **上限接线之外，这条压缩也得进 patch**（纯函数 + 5 条通道接线 + 配置字段 + 本表用例）。
5. **两条未接通道**（追加稽古 / 隐藏事件）先按现状钉住不动：报文里没有它们的 >1200 样本 ⇒ 不改。若要改，得先拿到样本，且量级本就是二阶（隐藏事件单次 ≤ +40、p=0.35；追加稽古每次 +20/+5），**未逐局统计过总贡献，别当缺口解释项**。

## 13. 压缩带进上游基线：两条 patch + 一处接缝证明（§12 待办 4 的落地）

### 13.1 先证明接缝：赛后奖励在**上游**也确实走 `Game::apply_event`

证明 = 两条端到端用例（`crates/matsuri-core/tests/softcap.rs`，只翻资产阈值、其余全同）：

| 用例 | 事件 | 结果 |
|---|---|---|
| `career_race_reward_channel_applies_soft_cap` | `race_career`（id 4001） | 五维逐维 = 未压增量的 ⌊½⌋ ✅ |
