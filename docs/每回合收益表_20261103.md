## 1 单手怎么切出来的

同一个回合里有两类报文：**带预告的 board 报文 P**（`home_info.command_info_array[].params_inc_dec_info_array`
非空）和**其后第一条带 `command_result` 的结算报文 R**。取 `delta = R.five − P.five` 就是这一手，
不用跨回合差分（跨回合会把事件增益混进来，`turn_gain.py` 那份就是被这个污染的）。
自检：**287 手里有 0 手在「预告没提到的轴」上动了**，说明配对是干净的。

`target_type` 口径照 `master.mdb single_mode_training_effect`：1速 2耐 3力 4根 5智 10体力 30技能点。

## 2 结论一：一手 = 两个加项，相加就是结算（97.9%）

| 来源 | 是什么 |
|---|---|
| `home_info.command_info_array[].params_inc_dec_info_array` | 训练本体（含支援卡、教え、人头、训练 Lv） |
| `festa_data_set.command_info_array[].params_inc_dec_info_array` | 大祭「作戦 / 合同練習 step」另外加的那一份 |

两者按 `target_type` **相加** = 玩家看到的最终增量：**281 / 287 手五轴逐轴全等（97.9%）**，
体力 92.9%、技能点 97.9% 逐手相等。剩下 6 手全是 `result_state=1`（失败：不给属性，体力反而 +10）。

只用 home 一项的话只有 8.4% 对得上——**引擎缺的就是这第二项**。

实例（run 172 t50，练速度 101）：home 速43 力14 → 结算 速61+；
另一手 5101（run 168 t40）：home 速100 力34 SP82 体力−25 + festa 速39 力11 SP38 **体力+12** 耐/根/智各10
→ 结算 速139 耐10 力45 根10 智10，**逐轴全等**（体力那一份是两项相抵：−25+12=−13）。

## 3 结论二：收益不按「距上限的剩余空间」衰减

组内（同 run 同 command 同轴）去均值回归，主轴增量对剩余空间：

- **β = −0.00078 ± 0.00500（t = −0.16，n = 103）** —— 与 0 不可区分。
- Pooled（不控组）ρ = −0.270、β = −0.0157±0.0037：这是**时间趋势混杂**
  （后面的回合既贴箱、buff 又厚），拿它当衰减证据就反了。
- 之前用跨回合差分得到的「单独练 β = −0.0205（t=−3.68）显著为负」就是这个混杂，作废。

⇒ 引擎里 `cap_decay` 这条（现置 0 停用）**没有报文依据，别复活**。上限只以第 4 节那条台阶起作用。

## 4 结论三：1200 软上限在训练增量上是真的，而且就是「超过 1200 之后减半」

同 (run, command, 训练Lv, 人头, 干劲) 格内，取练前<1200 那批手的最大值当名义值（不拟合）：

| 练前主轴值 | 名义 | 实测 home 主轴 |
|---|---|---|
| 856 / 894 / 1011 | 100 | 100 |
| 1189 | 100 | **55** |
| 1192 | 100 | **54** |
| 1353 / 1513 / 1705 / 1524 / 2006 / 2096 | 100 | **50** |

- 1189 那手正好落在引擎现有规则上：`below = min(gain, max(0, 1200−pre))`，结果 `below + (gain−below)/2`
  = 11 + 89/2 = **55**；1192 → 8 + 46 = **54**。两条都是逐位命中，不是趋势。
- 练前 ≥1200 之后**一律对半，与离 1200 多远无关**（1353 和 2096 都还是 50）⇒ 是台阶，不是曲线。
- 格内逐手核对整体命中 78.6%（224 手）；没命中的主要是同一格名义值本身还随体力/卡的落位变，
  不是规则形状不对。压缩手 `实测/名义` 的众数就是 0.50（27 手里 9 手正好 0.50，另有 0.46–0.54 一片）。

⇒ `soft_cap_gain()` 保留，**训练/稽古增量也走这条**（现在只接在训练上，赛后奖励那条已另案确认）。

## 5 结论四：287 手里钳位一次都没被触发

- 「预告 > 剩余空间」的组合 **0 个**；「练完正好等于上限」的组合 **0 个**；
  最贴箱的一手剩余 85、预告 84（差 1，不是相等）。
- 旁证：之前 288 张真机截图里也只有 1 手结算后正好顶格。

⇒ **上限在真机里基本不是靠钳位起作用的**；LF 五轴全超基础上限只能靠 §2b（上限延展）解释，
不能靠「练到墙上蹭过去」。这条仍然没测到机制，别写进代码。

## 6 每回合收益表（喂引擎的那张，home / festa 分开设）

口径：**只用「练前五轴都 <1200」的未压缩手 135 / 281 手**。
（把压缩手混进来会出假象：单独练 Lv3-5 那几行原本比 Lv2 还低，就是因为它们全是后期贴箱的手。）

读数：
1. **合练五维和里 festa 那一份占 43~47%**（未压缩手最高格 82.7 / 175.3），且它单独练几乎没有（Lv1 人头4 只有 2~4）。
   `act_training_step` 1 → festa 五维和均值 29.9，2 → 58.9。
2. home 项随 Lv 与人头单调涨（Lv1→Lv2 人头5：43→68），干劲 3→5 在同人头同 Lv 的格子里**接近翻倍**
   （16.9 vs 31.5）——但干劲没和「哪张卡落在哪一格」分离开，**别把它当干净乘区用**。
3. SP 跟着合练密度涨（合练 Lv2 人头5 一手 115.3，单独练 Lv1 人头4 只有 32.0）——
   这条对着 PT 缺口（校验侧 −20.2%）有直接意义：**PT 主要来源是合练人头，不是单独练次数**。
4. 表里的 n 都很小（9~19 手/格），**这是量出来的形状，不是可以填进配置的常数**；
   要接引擎就接 §2 那条结构（home + festa 两加项），festa 的公式还没拆出来（见 §7）。
