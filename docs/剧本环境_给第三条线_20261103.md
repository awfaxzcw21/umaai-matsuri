## 四、判据怎么跑（这条最容易出假账）

```bash
# 两臂各留一份 dist 二进制（一次性 worktree / 每臂一个 exe 的约定），从仓根跑
python tools/crn_gate.py --dist-a <臂A.exe> --dist-b <臂B.exe> --seeds 0,1,2 --n 4000

# 复用已有 dump：报告首行会打「重放旧 dump ≠ 新门禁」
python tools/crn_gate.py --dump-a a.jsonl --dump-b b.jsonl
```

它包的是 `matsuri-gate`，**没有自己新造任何判据**，只多做一件防假账的事：
**双臂同侧于锚点 ⇒ 「更近幅度」恒等于该分量的原始差值**（实测斜率 0.997、残差 ≤0.5），
此时判官给的「更近 / 更远」只是产出计，脚本把它降级成 `⚠️同侧·产出计(不可结论)`。

三条规矩（脚本已按这个印结论）：

- 只认**五维和 / 五维分 / PT** 三分量的**贴近幅度 95% 区间**：下界 >0 更近、上界 <0 更远、**跨 0 只留档不转正**。
- **同侧 ⇒ 不可结论**，换种子不会改变这件事，必须改臂或去锚点跑。
  定价类旋钮尤其注意：实测**只有「五维分」那一格不被产出污染**。
- **重放旧 dump ≠ 新门禁**：那只是对账。真门禁要同 `MC_N` / 同 `MC_SEED` 重新配对采样。

自检过的两件事：同臂喂自己 ⇒ 三分量全 `跨 0`（不会虚报提升）；
`rep_off_f05_s0` vs `rep_off_f20_s0` ⇒ 三分量全被标 `⚠️同侧·产出计`（不会被读成「变差了所以不能合」）。
锚点 = run179/cid179 终局真值 `[1998,1470,1656,1344,1573]` / 五维分 42,201 / PT 8,339，
`--five/--pt/--stat-score` 可换。
